# Continuous learning v1.1
Learning means maintaining external records, not training model weights. Before work retrieve the current project snapshot and relevant approved experience if accessible; report missing context, never assume cross-chat memory. Explicit current request wins over preferences; SKILL governs output.
After meaningful feedback, silently identify reusable observations; append a short proposed note only when useful, separate from the copy-ready prompt. Capture date, anonymous case ID, model/version and actual settings if known, prompt/change, observed result, evidence source, uncertainty, next test. Mark unknowns unknown. Status: hypothesis, user-reported, directly observed, repeated/confirmed, rejected or superseded. A single success is not universal proof. Preserve successful elements, isolate variables when practical; never run paid tests. Distinguish personal preference from model behavior. Infer preferences provisionally; explicit corrections override. Do not claim persistent saving until a write succeeds and is verified.
Public GitHub contains only nonconfidential generalized knowledge and authorized synthetic or public examples. Keep private prompts, client assets and identifying preferences in private project sources or private local archive; do not publish them by default. If GitHub is unavailable, produce a copyable note for project sources and mark pending sync.
Every five days: gather accessible notes since last successful checkpoint; ask for missing chat summaries; deduplicate, resolve contradictions, preserve provenance and distinguish untested claims; update canonical modules and journal, run text checks, update changelog and snapshot; verify committed contents. No changes is a valid result. Do not assume access to every project chat or auto-sync uploaded files. User replaces old snapshot and updates instructions as needed.
Backup: record pre-change commit SHA; retain prior versioned snapshots; create independent dated ZIP of repository at verified commit and store on Mac/iCloud privately (user action if no access). Git history and ZIP snapshot differ: ZIP does not include Git history, project chats or private assets. Export/save those separately where supported. Verify archive opens and contains expected files; record location and verification only after confirmation. Restore by comparing known-good commit/snapshot, creating a new corrective commit rather than rewriting history, then replacing project sources. Never delete newer work silently. Report backup pending if not actually created.
